关于如何更好地高性价比地使用 agent 框架 + API

发表于2026-10-21|更新于2026-10-21|观点
|浏览量:

本博客针对于使用各种框架壳子（claude/codex/dsh/hermes） + cc switch（真神把框架绑定制改调了，自由度拉满，操作简单，伟大无需多言，真心推荐） + 自己调用的各种包月或按量的api后台（mimo、ds、gpt、第三方等等）

1.什么决定了你使用ai的价格？

缓存：

也就api的记忆、上下文，ai每次回答你的问题，把之前和你对话的东西再读一遍，如果你的会话是连续的那这部分会很低；想象一下你在claude和ai聊了很久后，突然把它后面的脑子给换了（假设ds官方额度用完了，换成xiaomi mimo），那这个新脑子要把你当前上下文的东西再读一遍。这个新脑子可没有之前这些东西的影响。此时就会大量地命中非缓存。这个价钱是相当贵的。所以要避免会话中途切api

思考强度：

这个无庸置疑，你可以试试用同一个框架，调整不同的思考强度，发一句你好，每个框架可能消耗的token不同

api：

依旧无质疑，这个脑子是本地的，国外的，官网的，中转的都全然不同。国内按用量来说ds、mimo性价比较高了。

框架壳子：

目前我用的最顺手的就算codex、claude、hermes、dsh刚出没什么优势，常常写个插件把自己写死，但未来看好，让其在发酵一会生态

2.思路：越贵的越在上层，越按量的越在上层，越便宜的越在下层，越本地的越在下层，越按月的越在下层。

现在的框架沟通互相调用起来其实都比较方便，这给予了我们一定的操作性。

其实关于各自框架有一个概念叫做子agent，它的持久化还不确定。之前dsh刚出的时候，我用创作模式捣鼓自己的插件，最后表现的效果还是非常好的，但结果是非常烧钱。但其实有一个问题，这个过程是浪费时间和金钱的，因为github上有很多类似的项目或在经验。经典重复造轮子

但有一个问题想要降低缓存，并不是让每个agent+api的组合变成全能；而是让每个agent+api拥有一个专长，训练它们有一个专长。这样可以下派任务，想重复简单的任务交给本地模型，交给mimo，ds等，而且让他们保持这些会话通道畅通，可以更加地提高缓存命中。

比如：codex+gpt plus最顶层（仅负责发派任务和验收结果），hermes+ds作为中间力量，claude+mimo包月从事最低级的最基础的事情。

3.思考题：你现在有以下员工，如何更加高效地组织你自己的工作任务

A codex + gpt（领月薪120￥）

B hermes + ds (按量计价，喜欢别人放假的时候干活)

C claude + 本地llm（脑袋有点本，有点吃工作环境，优点是仅收点电费）

通过cc switch您还可以定制更多不同的员工。如opencode + mimo等等。还可以招募一些cc 管不了的dsh、workbuddy等等
