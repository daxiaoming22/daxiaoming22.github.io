大厂模型内卷受益外部消费者——如何白嫖workbuddy积分

发表于2026-11-24|更新于2026-11-24|教程
|浏览量:

本文的写法：默认 AI 补充，我出思想骨架。

【纲】是我的思想大纲（这段想说什么，我自己定），【人】是我的原话（一字未改，标在句号后）。没有标记的部分是 AI 照着骨架扩写的。

dsh+workbuddy插件+10个workbuddy账号，一天一千积分（标准版有额度4000积分/70￥），大概4天70块钱，一个月对于重度使用agent者来说可以省下500￥。【人】一百个账号就可以有5000￥，其实淘宝上已经有人在卖了，用他们自己的账号池，但自己的人脉圈，搭建的账号池，会更快更安全。【人】【目前对我来说dsh的插件生态已经日益成熟，很好用了，推荐大家去使用国产agent】【人】

中国的模型一直以开源、便宜著称，中国强电力，缺算力，使用市场份额很大；阿里、字节、腾讯等互联网大厂都在推自己的套餐都采用国内大模型聚合的模式，给用户自由选择模型的能力，字节这种功能在token plan、trae等api端都用这种模式，但是豆包办公领域一直用自家的模型-workbuddy依靠更加开放的模式，让我喜欢上wb。【人】

大厂的竞争，豆包工作也学workbuddy采用更加开放的方式去用每日额度+多模型选择的方式。【人】这给了我们很多收益的机会。【人】我们知道其实现实中真正使用wb的人是比较少的，身边的亲戚和同学都没用过。【人】所以随便借到10个账号是非常容易得到的（一家三口+同学+朋友+亲戚+双卡双待），之前介绍过cc switch,magpie,现在我真是彻底换到 dsh + dsh-connect-workbuddy 这条线上了。【人】

🧭 我的主力 agent 演进史

三个阶段，一条主线：把「订阅额度」从「只能在官方客户端里用」变成「在我写代码的地方用」，每换一次中间那层胶水就少一块。

【纲】这段骨架来自我原文第三段末尾那句「之前介绍过cc switch,magpie,现在我真是彻底换到 dsh + dsh-connect-workbuddy 这条线上了」——我这里想说的是换代的路径，不是工具测评。

第一阶段：cc switch + claude / hermes

  • 工具：cc switch + Claude Code / Hermes Agent。
  • 形态：换钥匙。手上有多套 API key / 多个供应商端点，cc switch 负责在它们之间一键切换，Claude Code 或 Hermes 负责跑 agent 循环。
  • 解决的是「今天用谁」——额度用完了切下一条线，不用改配置、不用重装。
  • 留下的问题：切换是手动的。你得知道哪条线还有额度，得自己判断该切了；多账号和多供应商在它眼里是一排并列的 key，不是一份会自动调度的资源池。

第二阶段：workbuddy — magpie + claude / hermes

  • 工具：WorkBuddy 账号池 + magpie + Claude Code / Hermes Agent。
  • 形态：把订阅里的模型掏出来。magpie 把 WorkBuddy 内部那批模型（GLM、DeepSeek、Kimi、MiniMax 等）暴露成标准接口，再喂给 Claude Code / Hermes 当后端。
  • 解决的是「用谁家的额度」——从「我买了哪家的 API」变成「我借到了哪家的账号」。这是省钱路线的真正起点，淘宝上卖账号池的人卖的就是这一层。
  • 留下的问题：还是三段式拼接。WorkBuddy → magpie → agent 框架，任何一段更新都可能断；账号轮换、积分读数、模型倍率这些信息全在框架外面，得靠人盯着。

第三阶段（现在，也是主力）：dsh + dsh-connect-workbuddy

  • 工具：dsh + dsh-connect-workbuddy。
  • 形态：胶水变成插件，装进 agent 框架自己肚子里。dsh-connect-workbuddy 是 dsh 的一个 bundle 插件，直接把本机已登录的 WorkBuddy 账号（国内版 workbuddy / 国际版 workbuddy-global）注册成 dsh 的模型供应商。
  • 关键差别，这一层不再只是转发请求：
    • 积分倍率跟着上游走。每次刷新自动读取每个模型的倍率（x0.79 这种），不写死也不猜，夜间折扣时卡片上的数字会一起变。
    • 多账号池 + 自动换号。账号是池子里可调度的资源，不再是一排要手动切的 key。
    • 逐模型开关图片输入、逐模型思考档位。能力差异在模型选择器里就标好了，不用记。
    • 只读积分概览 + 每日签到。还剩多少、今天签了没，在写代码的地方就能看见。
  • 为什么它成了主力：agent 框架、模型路由、账号池、额度视图，第一次在同一个进程里。以前是三段拼接（WorkBuddy → magpie → agent），现在是 dsh 内部的一个 provider；以前额度要开浏览器去查，现在输入框里就有胶囊读数。
  • 一句实话：它依赖的是 WorkBuddy 客户端自身的非官方接口，上游一收紧就得跟着改。这是这类工具的常态，不是这条路线独有的风险——第一阶段的 key、第二阶段的 magpie，风险结构完全一样，只是这次把风险收拢到了一个看得见的插件里。

两条读表提醒

  • 星标不等于好用。第 5 行 dsh-connect-workbuddy 只有 1,958 星，但它是我现在天天用的主力；第 3 行 Claude Code 15 万星，可它是闭源的。星标衡量的是「有多少人知道」，不是「适不适合你」。
  • 第 9 行 OpenCode 是开源的（MIT），主仓库已从 sst/opencode 迁到 anomalyco/opencode，22.8 万星，仍在活跃开发。网上能搜到的 opencode-ai/opencode 是已归档的旧仓库（archived: true，停在 2025-09），查资料时别找错地方。

几个容易混的点

  • dsh-connect-workbuddy 是 dsh 插件，用 dsh 安装；magpie-community/plugins 里的 workbuddy 包不是，它全名 @magpie-community/opencode-workbuddy-auth，是给 OpenCode 用的供应商插件。两者不是一个东西，别装错。
  • 第 8 行那个仓库是插件合集，331 星是整个仓库的，不是单个插件的。
